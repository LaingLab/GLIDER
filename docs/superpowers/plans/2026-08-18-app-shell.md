# Builder Shell Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the Builder's seven dock widgets, two toolbars and eight menus with one content surface, a collapsible panel each side, a permanent status strip and a command palette.

**Architecture:** A new `gui/shell/` package builds the frame from three standalone widgets, then `MainWindow` re-hosts its existing panel widgets into it. The shell becomes the Builder *page of the existing `QStackedWidget`*, which deletes a workaround rather than adding one.

**Tech Stack:** Python 3.11–3.13, PyQt6, pytest + pytest-qt, ruff + black at line length 100.

**Spec:** `docs/superpowers/specs/2026-08-18-app-shell-design.md`
**Mockup:** https://claude.ai/code/artifact/f3aa57bc-8788-4743-a711-fdbca94e0e68

Windows: `PYTHONPATH` separator is `;`. Verify once with `python -c "import glider; print(glider.__file__)"` that it resolves inside this worktree.

**Every GUI test must run against a `show()`n widget.** This is not stylistic. On the previous branch, 36 dialog tests passed while exercising a widget in a state no user occupies, because the fixture called `addWidget` but never `show()` — Qt installs default-button behaviour, focus and final geometry on the *show* event. Two of those tests were passing while asserting the exact opposite of reality. Any test here that does not show the widget is testing a different object than the one that ships.

Known pre-existing flake: `test_delay_node_is_accurate_under_realistic_loop_pressure` (Windows, ~1 in 5, marked slow). If it is the only failure, re-run it alone.

After each task: `ruff check src tests` and `black --check src tests` clean.

## What the code actually looks like — read before starting

Verified on `origin/main` at `00efa3b`:

- `main_window.py:266-276` — `self._stack = QStackedWidget()`, `setCentralWidget(self._stack)`, index 0 `_builder_view`, index 1 `_operator_view`.
- The seven docks are created at `:654, 662, 687, 701, 726, 747` and `:2211` (Analysis, built lazily).
- **Every dock wraps a standalone widget** — `_node_library_panel`, `_hardware_panel`, `_device_control_panel`, `_camera_panel`. Panel *contents* are re-hosted, not rewritten. This is what makes the work tractable.
- `main_window.py` is 2 639 lines. The shell lives in its own package to avoid growing it.

**Three ways the docks are load-bearing beyond holding a widget:**

1. `_BUILDER_DOCK_ATTRS` (`:598-604`) + `_hide_builder_docks()` / `_restore_builder_docks()` — docks live in `QMainWindow` dock areas *surrounding* the stack, so switching the stack does not remove them and they linger over the operator view (issue #39). Each dock's visibility is captured for restore.
2. The View menu uses `dock.toggleViewAction()` (`:938+`) — free Qt-provided show/hide actions that vanish with the docks.
3. `_move_camera_to_*` (`:568-590`) reparents `_camera_panel` between its dock and a dashboard slot.

**The architectural consequence, and the reason this design is worth building:** make `AppShell` the *Builder page of the stack* rather than something wrapping the window. Switching to the operator view then swaps the entire shell away, and `_hide_builder_docks`, `_restore_builder_docks`, `_BUILDER_DOCK_ATTRS` and the issue-#39 workaround are **deleted**. If you find yourself writing a hide-the-panels helper, stop — the design has gone wrong.

## Chunk 1: The pieces (Tasks 1–2)

### Task 1: `SidePanel`

**Files:** Create `src/glider/gui/shell/side_panel.py`, `src/glider/gui/shell/__init__.py`; test `tests/unit/gui/shell/test_side_panel.py`.

A tab strip over a content area, collapsible to a 34 px icon rail. It must know nothing about node libraries or cameras — tabs are supplied.

Required surface, because tests pin it: `add_tab(key, label, widget, icon_text)`; `set_current(key)`; `current_key()`; `expanded` property; `set_expanded(bool)`; `toggle()`; signal `expanded_changed(bool)`; signal `current_changed(str)`; `keys()`.

**Collapsed is a rail, not hidden** (spec §6). 34 px of icon buttons, each of which expands the panel to that tab. GLIDER has no existing users, so every user is a first-time user; a rail keeps the areas discoverable and gives back a click target that does not require knowing a shortcut.

- [ ] **Step 1: Write the failing tests** — against a shown widget:
  - adding tabs then `keys()` returns them in order
  - `set_current` changes `current_key()` and emits `current_changed` once
  - `toggle()` collapses, width drops to the rail width, `expanded_changed(False)` emitted
  - collapsed, the rail shows one button per tab
  - clicking a rail button expands *and* selects that tab
  - expanding restores the previous width, not a default
  - `set_expanded(True)` when already expanded emits nothing
  - a widget added to a tab is not destroyed by collapsing (it must survive to be re-shown)
- [ ] **Step 2: Run — expect `ModuleNotFoundError`**
- [ ] **Step 3: Implement**
- [ ] **Step 4: Run — all pass**
- [ ] **Step 5: Commit** — `feat(shell): a collapsible tabbed side panel`

### Task 2: `StatusStrip`

**Files:** Create `src/glider/gui/shell/status_strip.py`; test `tests/unit/gui/shell/test_status_strip.py`.

Fixed 40 px. Left to right: two panel-toggle buttons, experiment name with a dirty marker, run-state pill, spacer, one dot per device, `Ctrl+K` hint.

**This is the only chrome that cannot be summoned** (spec §5). Everything else is on demand; live hardware and recording state are not, because a board dropping 40 minutes into an unattended run must be visible without being asked for. Mockup state 3 is the case to satisfy: a device red *while recording*.

Colours come from `glider.gui.styles.colors` — `STATE_OK`/`STATE_WARN`/`STATE_ERR`, deliberately distinct from `ACCENT` so "needs attention" never competes with a primary action. **Set no colour in Python**: `objectName` plus a Qt `state` property, styled from `desktop.qss`, and call `style().unpolish()/polish()` on change or the pill keeps its old colour. This is the pattern `plugin_card.py` established; a widget-level `setStyleSheet` out-prioritises the app stylesheet and silently blocks theming.

Required surface: `set_experiment(name, dirty)`; `set_run_state(state)` for `idle`/`running`/`recording`/`error`; `set_devices(list[tuple[str, str]])` of `(name, state)`; signals `left_toggled()`, `right_toggled()`, `palette_requested()`.

- [ ] **Step 1: Failing tests** — shown widget: name and dirty marker render; each run state sets the pill's `state` property; devices render one dot each in order; changing a device's state repolishes; toggling emits; `Ctrl+K` hint present.
- [ ] Steps 2–5 as above. Commit: `feat(shell): the one strip that is always there`

## Chunk 2: The frame (Tasks 3–4)

### Task 3: `AppShell`

**Files:** Create `src/glider/gui/shell/app_shell.py`; test `tests/unit/gui/shell/test_app_shell.py`.

Composes `StatusStrip` above a horizontal splitter of `SidePanel | centre | SidePanel`. Takes the centre widget as a constructor argument — the shell does not know it is a node graph.

Required surface: `left`, `right`, `strip` properties; `set_centre(widget)`; `save_layout(settings)`; `restore_layout(settings)`.

**Layout persistence** (spec §8), under a `shell/` `QSettings` prefix: expanded state per side, active tab per side, both widths, window geometry. This is a plain bug fix riding along — `saveState`/`restoreState` are never called today, so the Builder resets every launch.

Failure posture, matching the vocabulary store: a malformed or partial value falls back to defaults and logs; it must never stop the app starting. Specifically —
- a saved tab key that no longer exists → first tab on that side
- geometry entirely off-screen (a rig whose second monitor is absent) → ignored, window centred
- missing keys → defaults

- [ ] **Step 1: Failing tests** — shown widget, injected `QSettings` (never the developer's real settings): round-trip of expanded state, active tab, widths and geometry; a saved tab that no longer exists falls back; off-screen geometry ignored; malformed values fall back and log; `set_centre` replaces without leaking the previous widget.
- [ ] Steps 2–5. Commit: `feat(shell): compose the frame, and remember it`

### Task 4: `MainWindow` re-hosts its panels

**Files:** Modify `src/glider/gui/main_window.py`; test `tests/unit/gui/shell/test_main_window_shell.py`.

**The risky step. Land it alone.**

`AppShell` becomes `_builder_view` — a page of the existing stack, not a wrapper around the window. Then:

- Left panel tabs: Nodes (`_node_library_panel`), Hardware (`_hardware_panel`), Files (files widget).
- Right panel tabs: Properties (the existing properties widget), Camera (`_camera_panel`).
- Centre: the existing graph/properties splitter contents.
- **Delete** the six Builder docks, `_BUILDER_DOCK_ATTRS`, `_hide_builder_docks`, `_restore_builder_docks` and their call sites. Switching the stack now swaps the shell away, so the issue-#39 workaround has nothing to do.
- **Keep** `_move_camera_to_*` working: `_camera_panel` still reparents between the right panel and the dashboard slot. This is the fiddliest part — a reparented widget that is later destroyed by its old parent is the classic Qt crash here.
- Analysis keeps its existing dock (spec §3) — it is a working surface, not an inspector, and forcing it into a tab repeats the mistake being removed.
- View-menu dock toggles used `dock.toggleViewAction()`, which disappears with the docks. Replace with actions driving `SidePanel.set_expanded`.

- [ ] **Step 1: Failing tests** — a shown `MainWindow`: the Builder page is an `AppShell`; all six panel widgets are reachable and are the *same objects* as before; switching to the operator view and back leaves no panel visible over the dashboard (the issue-#39 regression); camera survives a round trip to the dashboard and back; View-menu toggles collapse and expand.
- [ ] **Step 2: Run — expect failures naming the missing shell**
- [ ] **Step 3: Implement**
- [ ] **Step 4: Run the whole GUI suite** — every existing `main_window` test must pass unchanged. A failure there is a real regression, not a test to update.
- [ ] **Step 5: Commit** — `feat(gui): host the builder in the shell, and drop the docks`

## Chunk 3: Palette and finish (Tasks 5–7)

### Task 5: `CommandPalette`

**Files:** Create `src/glider/gui/shell/command_palette.py`; test `tests/unit/gui/shell/test_command_palette.py`.

`Ctrl+K` opens a centred overlay; typing filters; Enter runs; Escape closes.

**Sourced from the existing `QAction`s**, not a parallel registry — there are 30, they already carry text, shortcuts and enabled state, and a second list would drift from the first. Disabled actions render greyed rather than hidden, so the palette answers "can I do this yet?" as well as "where is it?".

Matching is subsequence-based (`sbj` finds "Add Subject…"), ranked by match position then text. No new dependency; the corpus is 30 items.

Note the shortcut: `Ctrl+K` must not collide with an existing binding — grep the actions before wiring it, and say so if it does.

- [ ] **Step 1: Failing tests** — matching and ranking are plain logic and can be tested without a window; the overlay itself against a shown widget: filter narrows, Enter triggers the selected action, Escape closes without triggering, a disabled action renders disabled and does not fire, empty corpus shows a named empty state rather than a blank box.
- [ ] Steps 2–5. Commit: `feat(shell): one keystroke to every action`

### Task 6: Slim the menu bar

**Files:** Modify `src/glider/gui/main_window.py`; test `tests/unit/gui/shell/test_menu_slimming.py`.

Keep **File, Edit, View, Help**. Move Experiment, Hardware, Run and Tools actions into the panels and the palette.

**Decision recorded in spec §9, flagged for veto:** the menu bar stays because on Windows and Linux an app without File → Save reads as unfinished, and because a menu bar is free inventory for a first-time user — which matters here more than in an app with a trained userbase.
